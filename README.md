# GitHub 仓库概览工具

一个使用 Python 编写的命令行学习项目。输入 GitHub 仓库的 `owner/repo`，程序会获取仓库名称、简介和主要语言，保存概览报告；随后展示根目录、识别三种配置文件，并按代码字节数计算和显示语言分布。最后获取并保存仓库的 README，支持按关键词查找其中的原文行。

这是完成 CS50P 后的第一个项目，重点是练习函数拆分、异常处理、第三方库、文件读写和单元测试。当前版本为 v0.6，不调用 LLM，也不需要数据库或 Web 框架。

## 当前功能

- 检查输入是否可以拆分为非空的所有者和仓库名，格式错误时允许重新输入。
- 请求 GitHub 仓库接口，获取仓库概览。
- 当简介或主要语言为 `None` 时，显示中文提示。
- 将三行仓库概览以 UTF-8 编码保存到 `report.txt`。
- 获取仓库根目录列表，用 `[目录]`、`[文件]` 和 `[其他]` 标签逐行显示条目。
- 识别根目录中的 `requirements.txt`、`pyproject.toml` 和 `package.json` 文件，逐行显示文件名和预设的用途说明。
- 没有匹配的配置文件时显示提示，继续后续的语言分布和 README 流程。
- 根目录请求出现网络异常或返回非 `200` 状态码时显示提示，继续获取语言分布和 README。
- 获取各语言的代码字节数，计算百分比，在终端逐行展示并保留一位小数。
- 语言数据为空或总字节数为零时，显示“暂无语言数据”。
- 语言请求出现网络异常或返回非 `200` 状态码时显示提示，继续获取 README。
- 请求仓库的 README 原文，在终端显示，并以 UTF-8 编码保存到 `repo_readme.txt`。
- 按关键词搜索 README，忽略大小写，逐行显示匹配结果，保留原文大小写和出现顺序。
- 没有匹配时显示提示；在关键词提示处直接回车或只输入空白可以跳过搜索。
- 对网络请求失败、非成功 HTTP 状态码和文件保存失败显示提示。

## 环境与安装

本项目的本地测试环境为 Python 3.12。实际查询需要能够访问 GitHub API。

第三方依赖记录在 `requirements.txt` 中：

- `requests`：发送 HTTP 请求。
- `pytest`：运行测试。

以下命令适用于 Windows PowerShell，请在项目目录中执行。

如果还没有虚拟环境，先创建一个；已有 `venv` 时跳过这一步：

```powershell
python -m venv venv
```

使用虚拟环境中的 Python 安装依赖：

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

这里直接指定了虚拟环境中的 Python 路径，因此不需要先激活虚拟环境。

## 使用方法

在项目目录运行：

```powershell
.\venv\Scripts\python.exe project.py
```

出现 `owner/repo:` 提示后，输入仓库所有者和仓库名，例如：

```text
pallets/flask
```

不要输入完整的网页地址。`pallets` 是所有者，`flask` 是仓库名。

仓库信息请求成功时，终端会显示概览；概览文件保存成功后，提示“报告已保存”。生成的 `report.txt` 内容示例：

```text
仓库: pallets/flask
简介: The Python micro framework for building web applications.
语言: Python
```

### 查看仓库根目录

概览保存成功后，程序请求仓库根目录列表。成功时，每个条目显示名称和类型标签。以下是格式示例，不是 `pallets/flask` 的完整目录：

```text
仓库根目录: [目录] docs
[文件] README.md
```

- 接口中的 `dir` 显示为 `[目录]`，`file` 显示为 `[文件]`，其他类型显示为 `[其他]`。
- 按接口返回的顺序显示，只列出根目录这一层，不进入子目录，也不下载其中的文件内容。
- 目录列表只显示在终端，不写入概览报告，也不生成额外文件。
- 根目录请求出现网络异常时显示“目录请求失败”；返回非 `200` 状态码时显示“暂时无法获取目录: 状态码”。这两种情况都不会阻止后续的语言分布和 README 请求。

### 识别配置文件

根目录请求成功后，程序先打印目录列表，再用同一份目录数据识别配置文件，不会为此增加网络请求。目前的规则如下：

| 文件名 | 程序显示的用途说明 |
| --- | --- |
| `requirements.txt` | Python 依赖清单 |
| `pyproject.toml` | Python 项目配置 |
| `package.json` | JavaScript/Node.js 项目配置 |

只有条目的 `type` 为 `file`，且文件名与规则中的名称完全一致时，才生成说明。文件名匹配区分大小写；同名目录和不在规则表里的文件都会被忽略。多个匹配结果按目录数据中的顺序逐行显示。

除了 `pallets/flask`，也可以在 `owner/repo:` 提示处输入 `expressjs/express`。当返回的根目录中包含 `package.json` 文件时，配置识别部分会显示：

```text
package.json: JavaScript/Node.js 项目配置
```

如果目录为空，或者没有任何条目符合这三条规则，程序会显示“未在根目录发现这三种配置文件”。无论有没有匹配，都继续获取语言分布和 README；如果根目录请求出现前面提到的网络异常或非 `200` 状态码，则跳过配置识别，继续后续流程。

这是一种基于文件名的规则识别：用途说明来自程序中的字典，不是读取文件内容后得出的结论。发现文件不代表已经确认了具体依赖或整个项目的技术栈；没有匹配也不代表仓库没有配置文件或没有使用相关语言。

### 查看语言分布

目录和配置识别步骤结束后，程序通过 `GET /repos/{owner}/{repo}/languages` 获取语言统计。这个接口返回“语言名称 → 代码字节数”的数据，不是代码行数或文件数量。统计口径见 [GitHub 官方文档](https://docs.github.com/en/rest/repos/repos#list-repository-languages)。

程序用各语言的字节数之和作为总数，计算：

```text
语言占比 = 该语言的代码字节数 ÷ 接口返回的所有语言代码字节数之和 × 100
```

例如，假设返回 Python 为 800 字节、JavaScript 为 200 字节，终端会显示：

```text
语言分布（按代码字节数）: Python: 80.0%
JavaScript: 20.0%
```

以上仅为演示数据，不代表 Flask、Express 或其他真实仓库当前的语言比例。实际结果以本次接口返回为准。

- 每个百分比保留一位小数；逐项舍入后，显示值之和不一定恰好等于 `100.0%`。
- 按接口返回的顺序逐行显示，目前不额外按占比排序，也不绘制图表。
- 当返回空字典，或者所有语言的总字节数为零时，显示“暂无语言数据”，不进行除法计算。
- 请求出现网络异常时显示“语言请求失败”；返回非 `200` 状态码时显示“暂时无法获取语言分布: 状态码”。这两种情况都继续后续的 README 流程。
- 语言分布只显示在终端，不写入 `report.txt` 或 `repo_readme.txt`，也不生成额外文件。

语言占比是代码字节数的比例，不能直接代表项目复杂度、代码质量或完整技术栈。

### 获取 README

语言分布步骤结束后，程序继续请求 README。README 请求成功时，终端显示正文；正文文件保存成功后，提示“README已保存”。实际信息以查询时的接口返回为准。

### 搜索 README

README 获取并保存成功后，程序会提示 `输入关键词:`。例如输入：

```text
fLaSk
```

程序会在本次获取的 README 正文中查找，并逐行打印包含该关键词的原文。比较时会把关键词和当前行转换成小写，所以 `fLaSk` 也能匹配 `Flask` 或 `FLASK`；输出仍然保留原文的大小写。

- 输入关键词时，程序会去掉首尾空白。
- 找到多行时，按它们在原文中的顺序显示；没有匹配时，显示“未找到匹配内容”。
- 直接回车或只输入空白时，显示“已跳过搜索”并结束，之前已经保存的文件不受影响。
- 搜索使用已经获取到的正文，不会再次发送网络请求，也不会重新读取本地报告。
- 程序会先显示 README 全文，再询问关键词。输入关键词后出现的内容才是本次搜索结果。

当前每次运行只接受一次关键词输入，显示结果或跳过后就结束。搜索结果只显示在终端，不另外保存，也不会把 `repo_readme.txt` 替换成筛选后的内容。

如果查询的是 `expressjs/express`，可以输入 `ExPrEsS` 试用 README 搜索。这里的关键词搜索忽略大小写，与前面配置文件名的精确匹配不同。

### 输出文件

仓库概览和 README 都保存成功后，会得到两个输出文件：

- `report.txt`：仓库名称、简介和主要语言组成的三行概览。
- `repo_readme.txt`：从目标仓库获取的 README 正文，可能包含标题、链接、代码块和 HTML 标记。程序只保存文本，不渲染或分析这些标记。

目录列表、配置文件识别结果、语言分布和关键词搜索结果都只显示在终端，不写入这两个文件，也不生成第三个输出文件。

两个文件都保存到**运行命令时所在的目录**。按上面的方式从项目目录运行，就会保存在项目目录中。它们与本项目的使用说明 `README.md` 是不同的文件，不会覆盖这份说明。

每次执行到文件保存步骤时，会以覆盖写入方式保存对应内容，并在文本末尾追加一个换行，不会累积历史报告；需要保留旧文件时，请在再次运行前自行备份。

如果 README 请求失败，已经保存的概览仍然保留。如果本次没有进入 README 保存步骤，已有的 `repo_readme.txt` 也会保留旧内容。因此，请结合本次终端提示判断是否成功更新，不能仅凭文件存在判断下载成功。

## 项目文件

- `project.py`：命令行入口、交互输入与解析、仓库信息/根目录/语言统计/README 请求、格式化与展示、配置文件识别、文件保存和关键词搜索。
- `test_project.py`：输入解析与重试、报告格式、文件保存、关键词搜索、目录格式化与超时处理、配置文件识别和语言分布格式化的单元测试。
- `requirements.txt`：第三方依赖清单。
- `report.txt`：概览保存成功后生成的报告，不需要提前创建。
- `repo_readme.txt`：README 保存成功后生成的正文文件，不需要提前创建。
- `README.md`：项目介绍和使用说明。

## 当前限制

- 当前可以获取仓库概览、根目录列表、语言统计和 README 正文，但不递归查看子目录，不读取其他文件的源码，也不评价代码质量。
- 配置识别仅检查根目录中的三种精确文件名和条目类型，不读取配置内容，不提取依赖或版本，也不能据此完整判断项目使用的技术。
- 语言分布依赖 GitHub 返回的统计结果，不在本地扫描或识别源码语言；只展示字节数占比，不生成图表或写入概览文件。
- README 搜索是按行进行的普通子串匹配，不支持正则表达式、语义理解、内容总结或安装说明提取。
- 搜索只返回匹配行，不附带行号或上下文段落；不会解析 Markdown 或 HTML 结构。
- 未配置身份认证，面向可匿名访问的公开仓库。
- 所有请求均设置 `timeout=10`，不自动重试。仓库信息或 README 请求出现网络异常、返回非 `200` 状态码时，程序显示提示并结束；根目录请求遇到这两种情况时，显示提示后继续语言分布和 README 流程；语言请求遇到这两种情况时，显示提示后继续获取 README。
- 概览或 README 文件保存失败时，程序显示提示并结束，需要自行重新运行。
- 仓库没有可获取的 README 时，程序按非成功 HTTP 状态码处理，不单独判断失败原因。
- JSON 解析和格式化依赖接口返回预期的数据结构与字段，尚未处理无效 JSON、缺少字段等所有异常响应情况；这类异常仍可能使程序中断。

## 学习内容

### CS50P 基础知识

- 函数与变量：拆分程序职责，通过参数和返回值传递数据。
- 条件与循环：判断输入、检查请求结果，以及让用户重新输入。
- 异常处理：使用 `try`、`except` 和 `raise` 处理错误。
- 库与字典：使用 `requests`，将 JSON 响应解析为字典并读取字段。
- 文件读写：使用 `with open(...)` 保存和读取 UTF-8 文本。
- 单元测试：使用 `pytest`、`assert` 和 `pytest.raises` 检查函数行为。

### v0.2 中进一步练习的知识

- 请求头与字典传参：用 `Accept` 请求头指定 README 原文格式，将字典传给 `requests.get` 的 `headers` 参数。
- 响应对象与正文：使用 `status_code` 判断结果，用 `.json()` 解析仓库信息，用 `.text` 读取 README 正文。
- 函数复用：通过传入不同的文本和文件名，让同一个 `save_report` 保存概览与 README。
- 临时目录测试：通过测试函数的 `tmp_path` 参数接收 pytest 提供的临时目录，拼接文件路径，完成“保存、读回、比较”的检查。

### v0.3 中进一步练习的知识

- 字符串与列表：用 `.splitlines()` 将正文拆成行，用 `.lower()` 配合 `in` 判断匹配，用 `.append()` 收集结果。
- 返回值与显示分工：`search_readme` 负责返回匹配行列表，`main` 负责接收用户输入和逐行打印结果。
- 提前返回：搜索函数遇到空关键词时返回空列表；主程序遇到空输入时提示跳过并结束。
- 测试驱动的小练习：先为非空正文、空关键词的情况写测试，确认测试失败，再补上判断让测试通过。

### v0.4 中进一步练习的知识

- 列表与字典组合：遍历目录条目列表，从每个字典中读取 `name` 和 `type`。
- 条件分支：用 `if`、`elif` 和 `else` 为目录、文件和其他类型选择标签。
- 字符串拼接：用 `.append()` 收集每一行，再用 `"\n".join(lines)` 拼成多行文本；空列表会得到空字符串。
- 数据转换与职责分工：请求函数返回响应对象；当前实现中，`show_contents` 用 `.json()` 解析出目录列表，交给 `format_contents` 格式化后再打印，`main` 只负责调用展示函数。
- 异常后的流程：当前实现用 `try`、`except` 和提前 `return` 处理目录请求失败，再单独检查 HTTP 状态码。请求没有抛出异常，不代表状态码一定是 `200`；展示函数返回后，`main` 可以继续后续步骤。
- 单元测试：用自己构造的目录数据检查格式化结果，不依赖真实网络请求。

### v0.5 中进一步练习的知识

- 字典作为规则表：`rules` 的键是文件名，值是用途说明；用 `name in rules` 检查键是否存在，再用 `rules[name]` 读取对应的值。
- 组合条件：用 `and` 要求条目类型为文件、文件名在规则表中这两个条件同时成立。
- 规则与结果分开：规则字典描述所有可识别的文件，`results` 列表只收集本次目录里实际匹配的条目；列表放在循环外初始化，遍历结束后再返回。
- 列表的真假判断：`if analysis_results` 在列表非空时进入分支，空列表则进入 `else`，显示未发现匹配文件的提示。
- 分析与显示分工：`analyze_contents` 接收目录数据并返回说明列表，当前由 `show_contents` 逐行打印或显示无匹配提示，随后返回 `main`，继续语言分布和 README 流程。
- 单元测试：用构造的数据检查正常匹配、应当忽略的条目和空目录；比较整个列表时，同时检查结果内容与顺序。

### v0.6 中进一步练习的知识

- 字典遍历与求和：用 `.values()` 获取语言字节数，用 `sum()` 计算总数，用 `.items()` 同时获取语言名称和字节数。
- 百分比与格式化：用当前语言的字节数除以总数再乘以 100，用 f-string 的 `:.1f` 保留一位小数，并用换行符连接结果。
- 边界处理：总数为零时提前返回提示，同时处理空字典，避免除以零。
- 请求、格式化与展示分工：`fetch_languages` 返回响应对象，`format_languages` 将字典转换为字符串，`show_languages` 处理请求结果并打印，`main` 安排调用顺序。
- 可读性重构：为变量和函数使用能表达用途的名字；将交互输入提取到 `prompt_repository`，将目录与语言展示放入各自的函数，减少 `main` 中的细节。
- 提前返回的作用范围：`show_languages` 因请求失败而 `return` 时，只结束这次函数调用，不会直接结束调用它的 `main`。
- 可重复的测试：为语言格式化编写正常数据、空字典和总数为零的测试；通过 `monkeypatch` 模拟用户输入与目录超时，通过 `capsys` 检查打印结果。
